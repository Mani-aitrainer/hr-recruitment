Presenter handy guide

Every file in the HR Recruitment job posting monorepo, with the one instruction it carries. Use it to answer "what is in that file?" without opening it.

The one-line story

Documents come first, the agent harness enforces them, and the code is generated against both.

proposal → plan → spec → review → code

Two standing rules

Each project's README is written with its code, not before it. Every behaviour gets a positive and a negative test.

CLAUDE.md · plan §1 · proposal §5.5

What exists today

Documents and the harness are done. The four projects are scaffolded live during the demo.

docs/ + .claude/ = ready

If someone asks "where is that enforced?" — a rule states it, a skill walks through it, an agent checks it, and settings.json blocks what must never happen. The same instruction usually appears in all four, which is the point: guidance in the documents, enforcement in the harness.
